# Webサービス開発100本ノック2026

> この資料は，九州大学 大学院芸術工学研究院 コンテンツ環境デザイン研究室（牛尼研）の研究室ワークショップ（手を動かして学ぶ演習）のために作成したものです．
> 研究室のWebサイト：https://www.design.kyushu-u.ac.jp/~ushiama/

この「Webサービス開発100本ノック2026」は，Webサービス構築に必要な基礎から応用までを段階的に体験しながら学ぶための課題集です．
10のテーマごとに10課題ずつ，合計100課題で構成されています．
各課題はGitHubを用いた提出を原則とします．

---

## ワークショップ形式での進行

本演習は**研究室ワークショップ**として，**毎週1テーマごと**に進めます．
（例：1週目はテーマ0，2週目はテーマ1……）
各テーマは，ミニマムな知識から少しずつ発展できる構成になっています．

---

## グループ分け

- グループ分け（メンター・メンバー）は，研究室内で別途連絡します．
- 各課題はスプレッドシートでグループに割り当てられています．グループ内で誰がどの課題を担当するかを話し合って決め，担当者欄に名前を記入してください．
- メンターは，グループのメンバーの質問に答えたり，提出物を確認したりしてサポートします．
- メンターが課題を担当しても問題ありません．

## 開発環境（2026年度の推奨）

| 項目 | 推奨 | 備考 |
|:--|:--|:--|
| エディタ | Visual Studio Code | 拡張機能は各自自由 |
| Node.js | **24 LTS 以降** | `node -v` で確認．nvm／fnm／Volta等のバージョン管理ツールの利用を推奨 |
| パッケージ管理 | npm（Node.js付属） | pnpm等を使ってもよい |
| ブラウザ | Google Chrome等 | デベロッパーツールを多用する |
| Webサーバ | Express 5 | `npm install express` で導入される現行版 |
| UIフレームワーク（テーマ7〜） | React 19 ＋ Vite **または** Streamlit（Python 3.12以降） | 選択制．Create React Appは2025年に非推奨化されたため使わない |
| データベース | SQLite | Node.js組み込みの `node:sqlite`，または `better-sqlite3` |
| 公開 | GitHub Pages／Render／Streamlit Community Cloud | 静的サイトはGitHub Pages，サーバアプリはRender，StreamlitアプリはStreamlit Community Cloud |

## 課題の進め方・提出フロー

1. **各自のGitHubアカウントでリポジトリ作成**
各テーマごと，課題用のリポジトリ（例：`web-knock-0`など）を自分のGitHubアカウントで作成してください．

2. **課題の作成・コミット・プッシュ**
課題を解き，成果物やドキュメントをコミットし，GitHubにプッシュしてください．
課題ごとにディレクトリ（例：`00/`，`01/`）を分け，リポジトリ直下のREADME.mdに各課題へのリンクを置くと見やすくなります．

3. **リポジトリURLをスプレッドシートに提出**
毎週，担当一覧のスプレッドシートの担当部分に**リポジトリのURL**を記入してください．
    - スプレッドシートのURLは，研究室内で別途連絡します．

## 質問・誤記の報告

- 課題についての質問や，資料の誤り・分かりにくい点は，このリポジトリの **[Issues](../../issues)** に投稿してください（テンプレートを用意しています）．
- 誤字などの修正は，**Pull Request** で直接送ってもらっても構いません（[CONTRIBUTING.md](CONTRIBUTING.md) を参照）．テーマ0で学ぶ内容の実践練習になります．
- 提出用リポジトリのひな形は [template/](template/) にあります．

---

## 注意事項

- **パスワード，APIキー，`.env` ファイル等の秘密情報は絶対にコミットしないこと．** 誤ってpushした場合は，ファイルを消すだけでなくキーそのものを無効化（再発行）すること．
- スクリーンショットに個人情報やトークンが写り込んでいないか，提出前に確認すること．
- 提出用リポジトリとIssuesは誰でも見られます．実名・学籍番号・メールアドレスなどの個人情報は書かないこと（名前欄はニックネームやGitHubのアカウント名でも構いません）．
- コミットに記録するメールアドレスには，GitHubの公開用アドレス（`…@users.noreply.github.com`）を使うこと（テーマ0の課題00を参照）．
