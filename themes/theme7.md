# テーマ7：UIフレームワーク入門（React／Streamlit 選択制）

[← テーマ6](theme6.md) ｜ [概要](../README.md) ｜ [テーマ8 →](theme8.md)

本テーマでは，UIフレームワークを用いて「状態（データ）から画面を組み立てる」考え方を習得する．
部品（コンポーネント）への分割，状態管理，入力イベントの処理，ページ構成，公開という一連の流れを体験する．

フレームワークは，以下の **トラックA（React）** と **トラックB（Streamlit）** のどちらかを選ぶこと．
課題番号と学ぶ概念は両トラック共通であり，書き方だけが異なる．

---

## トラックの選び方

| | トラックA：React | トラックB：Streamlit |
|:--|:--|:--|
| 言語 | JavaScript（JSX） | Python |
| 向いている人 | Webサービスそのものを作りたい人，UIを細かく作り込みたい人 | 研究で推薦・機械学習・生成AIのプロトタイプやデモ，評価用画面を作りたい人 |
| 特徴 | 世界で最も広く使われるフロントエンドライブラリ．生成AIが出力するUIコードの多くもReact | Pythonだけで画面が作れる．データ分析・機械学習のコードをそのまま画面にできる |
| 苦手なこと | 環境構築や約束事（Hooks等）が多い | 見た目の細かな作り込み，大規模・多人数向けのサービス |
| 公開先 | GitHub Pages／Render（Static Site） | Streamlit Community Cloud |

- 迷ったら，**自分の研究で使う言語に合わせる**とよい（Python中心ならトラックB）．
- 機械学習モデルのデモに特化したい場合は，トラックBの代わりに **Gradio** を使ってもよい（課題の読み替えは各自で行い，READMEに明記すること）．
- 選んだトラックをREADME.mdの冒頭に書くこと．

### 環境の準備

- **トラックA**：Node.js 24 LTS以降．2025年度まで使っていた Create React App は2025年に非推奨となったため，**Vite** を用いる．
- **トラックB**：Python 3.12以降．プロジェクトごとに仮想環境を作ること（`uv` の利用を推奨．`python -m venv` でもよい）．

## 課題一覧

---

### 70. プロジェクトの作成と起動

- **A**：`npm create vite@latest` でテンプレートに「React」（JavaScript）を選び，新規プロジェクトを作成せよ．`npm install` → `npm run dev` で起動し，初期画面を表示すること．
- **B**：仮想環境を作成してStreamlitをインストールし（`uv init` でプロジェクトを作ってから `uv add streamlit`，または `python -m venv .venv` で仮想環境を作ってから `pip install streamlit`），`st.title("Hello, Streamlit!")` だけを書いた `app.py` を `streamlit run app.py` で起動すること．

**提出物**
- プロジェクト作成・起動コマンド
- 初期画面のスクリーンショット

---

### 71. 最初の部品（コンポーネント）の作成

- 自己紹介を表示する部品を作成し，メイン画面に組み込んで表示せよ．
- **A**：関数コンポーネント `<Profile />` を作成し，`App` に組み込む．
- **B**：`st.header`，`st.write`，`st.image` などを使って自己紹介を表示する関数 `show_profile()` を作成し，`app.py` から呼び出す．

**提出物**
- 部品のソースコード
- 表示画面のスクリーンショット

---

### 72. 部品へのデータの受け渡し

- 部品の外からデータ（例：名前や所属）を渡し，同じ部品で異なる内容を表示できるようにせよ．
- **A**：親コンポーネントから子コンポーネントへ **props** で渡す．
- **B**：関数の **引数** で渡し，同じ関数を2回以上呼び出して別の人物を表示する．

**提出物**
- 該当するソースコード
- 表示画面のスクリーンショット

---

### 73. 状態管理（カウンター）

- ボタン押下で値が増減するカウンターを作成せよ．
- **A**：`useState` フックを用いる．
- **B**：`st.button` と `st.session_state` を用いる．Streamlitは**操作のたびにスクリプト全体が上から再実行される**ため，普通の変数では値が保持されないことを確認し，その理由をまとめること．

**提出物**
- カウンターのソースコード
- 動作画面のスクリーンショット
- （B）再実行モデルについてのまとめ

---

### 74. リストの動的描画

- 配列（リスト）データ（例：TODOリストや果物リスト）を繰り返し処理で画面に表示せよ．
- **A**：`map` で描画し，各要素に適切な `key` を付けること．`key` が必要な理由を一言まとめること．
- **B**：`for` 文で `st.write` 等を使って表示すること．あわせて，辞書のリストを `st.dataframe` で表として表示すること．

**提出物**
- リスト描画のソースコード
- 表示画面のスクリーンショット

---

### 75. フォーム入力とイベント処理

- テキストボックスに入力した内容を，ボタン押下時にリストへ追加する機能を実装せよ．
- **A**：入力値とリストを `useState` で管理する．
- **B**：`st.form` と `st.text_input` を用い，リストは `st.session_state` に保持する．
- テーマ3（38）でバニラJSで作った機能と比べ，書き方の違いを一言まとめること．

**提出物**
- フォームとリストのソースコード
- 入力・追加の動作画面のスクリーンショット

---

### 76. 「いつ処理が実行されるか」の制御

- 画面の更新とは別に行う処理（副作用・重い処理）の実行タイミングを制御せよ．
- **A**：`useEffect` を用い，状態が変わるたびに `document.title` を書き換える，または `localStorage` へ保存する処理を実装する．依存配列（第2引数）を変えると実行タイミングがどう変わるか確認し，開発モード（StrictMode）でエフェクトが2回実行される理由も調べること．
- **B**：`time.sleep(3)` などで時間のかかる関数（重いデータ読み込みの代わり）を作り，`@st.cache_data` を付けた場合と付けない場合で，ボタン操作時の待ち時間がどう変わるか確認すること．

**提出物**
- 該当するソースコード
- 動作確認のスクリーンショットと，実行タイミングについてのまとめ

---

### 77. 画面の分割とレイアウト

- 複数の部品を組み合わせて，1つの画面を構成せよ．
- **A**：ヘッダー・フッター・メイン等のコンポーネントをそれぞれ別ファイルに作成し，`App` で組み合わせる．
- **B**：`st.sidebar`，`st.columns`，`st.tabs` を用いて画面を区切り，部品となる関数は別のモジュール（`.py` ファイル）に分けて `import` する．

**提出物**
- 各部品のソースコード
- 組み合わせた画面のスクリーンショット

---

### 78. 複数ページ構成

- 複数ページ（例：Home，About）を持つアプリを作成し，ページ間を移動できるようにせよ．
- **A**：React Router（v7，パッケージ名は `react-router`）を用い，ページ間のリンク（`<Link>`）も設置する．
- **B**：`st.navigation` と `st.Page` を用いてページを登録する．

**提出物**
- ページ構成のソースコード
- ページ遷移の動作画面のスクリーンショット

---

### 79. アプリの公開

- 作成したアプリをインターネット上に公開し，URLを確認せよ．
- **A**：`npm run build` でビルドし，GitHub PagesまたはRender（Static Site）で公開する．GitHub Pagesの場合は `vite.config.js` の `base` 設定が必要になる点，ルーティングしたページで再読み込みすると404になる問題とその対処に注意すること．
- **B**：GitHubリポジトリに `requirements.txt`（または `pyproject.toml`）を含めてpushし，Streamlit Community Cloudで公開する．

**提出物**
- 公開URL
- 公開画面のスクリーンショット
